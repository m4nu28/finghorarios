# Purpose

Use this skill after implementing or modifying any UI.

Do not assume a screen is finished because it works. Review it as if you were a senior product designer performing a design review.

# Review mindset

Evaluate the interface, do not defend it.

Look for problems before looking for successes.

Always provide concrete improvements.

# Product context

The audience is primarily FING students.

The application is used to:

- Find courses.
- Compare schedules.
- Explore careers.
- Understand prerequisites.
- Plan semesters.

The interface should optimize speed of understanding.

# Review categories

## Visual hierarchy

Check:

- Is the primary action obvious?
- Are headings meaningful?
- Is spacing consistent?
- Does typography create hierarchy?
- Is information easy to scan?

## UX

Check:

- Number of clicks.
- Confusing interactions.
- Missing feedback.
- Loading state.
- Empty state.
- Error state.
- Success feedback.

## Information density

Avoid both extremes.

Too little information wastes space.

Too much information overwhelms users.

## Accessibility

Verify:

- Keyboard navigation.
- Focus visibility.
- Contrast.
- Labels.
- Semantic HTML.
- Click targets.

## Consistency

Verify:

- Buttons behave consistently.
- Colors have consistent meaning.
- Icons are reused consistently.
- Terminology matches the rest of the application.

## Responsiveness

Test:

- Small laptop.
- Large desktop.
- Mobile.

Schedule grids may scroll horizontally if necessary.

## Academic realism

Use realistic examples:

- Long course names.
- Multiple groups.
- Overlapping schedules.
- Many prerequisites.

Do not review only ideal mock data.

# Anti-patterns

Flag interfaces that resemble:

- Generic SaaS dashboards.
- Crypto applications.
- AI-generated templates.
- Marketing landing pages.

Specifically watch for:

- Too many cards.
- Decorative gradients.
- Glassmorphism.
- Huge hero sections.
- Meaningless statistics.
- Decorative icons without purpose.
- Excessive whitespace.

# Review output

Structure feedback using:

1. Strengths.
2. Issues.
3. Severity.
4. Suggested improvements.
5. Quick wins.

Prioritize problems that significantly improve usability.

# Completion checklist

Before approving a UI:

- Navigation is obvious.
- Main tasks are fast.
- States are complete.
- Accessibility basics pass.
- Visual hierarchy is clear.
- Design feels specific to FingHorarios.
