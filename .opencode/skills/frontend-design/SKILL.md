# Purpose

Use this skill whenever creating or redesigning user interfaces.

The goal is to build a tool that feels made specifically for FING students, not a generic SaaS dashboard.

# Design philosophy

The interface should be:

- Fast to understand.
- Information first.
- Clean.
- Practical.
- Calm.
- Consistent.
- Dense enough to be useful.

Avoid unnecessary decoration.

# Visual identity

The application should feel like:

- A modern university tool.
- An engineering application.
- A productivity interface.

It should not feel like:

- A crypto website.
- A startup landing page.
- A generic admin template.
- An AI-generated dashboard.

# Layout

Prefer:

- Clear page hierarchy.
- Predictable navigation.
- Consistent spacing.
- Strong typography.
- Simple grids.

Avoid wrapping every section in cards.

# Color

Use a restrained palette.

One primary accent color is usually enough.

Reserve color for:

- Actions.
- Selection.
- Status.
- Feedback.

Avoid rainbow interfaces.

# Typography

Typography carries hierarchy.

Use:

- Clear headings.
- Readable body text.
- Consistent spacing.

Avoid oversized marketing headlines.

# Components

Every component should have an obvious purpose.

Prioritize:

- Tables.
- Timelines.
- Schedule grids.
- Search.
- Filters.

Decorative widgets should never distract from academic information.

# Forms

Forms should be short and obvious.

Always include:

- Labels.
- Validation.
- Helpful errors.
- Keyboard navigation.

# Empty states

Every screen should have:

- Loading state.
- Empty state.
- Error state.

Empty states should explain what the user can do next.

# Responsive design

Support desktop first without ignoring mobile.

Never compress timetable content until unreadable.

Horizontal scrolling is acceptable for schedule grids.

# Motion

Animations should communicate interaction.

Avoid decorative animations.

Respect reduced motion preferences.

# Accessibility

- Semantic HTML.
- Visible focus.
- Keyboard support.
- Good contrast.
- Large click targets.

# Review checklist

Before finishing a screen ask:

- Does this look like a university tool?
- Can a student understand it in seconds?
- Is decoration competing with information?
- Can I remove something without hurting usability?
- Does it still work with realistic data?
